# Southern Zero Dropout Platform

**“มองเห็นทุกคน ออกแบบโอกาสเฉพาะบุคคล”**
ระบบกลางสำหรับผู้บริหารพื้นที่ สถานศึกษา ครูผู้จัดการรายกรณี และหน่วยงานที่รับส่งต่อ
ใช้ดูแลเด็กตั้งแต่เริ่มมีความเสี่ยง จนกลับเข้าสู่การเรียนรู้หรือมีอาชีพอย่างมั่นคง

ต้นแบบ (prototype) สำหรับ **พื้นที่จังหวัดชายแดนภาคใต้ (จชต.)** ตามขอบเขต TOR — **ปัตตานี ยะลา นราธิวาส**

---

## ทำไมต้นแบบนี้ต่างจากระบบเฝ้าระวังทั่วไป

ระบบ EWS ของโรงเรียนมองเห็นเฉพาะ “เด็กที่ยังอยู่ในระบบ” และแก้ปัญหาได้เฉพาะเรื่องที่โรงเรียนทำเองได้
ต้นแบบนี้ตั้งอยู่บนข้อสังเกตสามข้อจากพื้นที่ จชต. และออกแบบตามนั้นทั้งระบบ:

| ข้อสังเกต | สิ่งที่ระบบทำ |
|---|---|
| ครึ่งหนึ่งของปัญหาคือเด็กที่ **ไม่อยู่ในทะเบียนโรงเรียนแล้ว** | **ทะเบียนเด็กนอกระบบ** รับข้อมูลจาก 7 ช่องทาง (โรงเรียน / อบต. / ประชาสังคม / ผู้นำศาสนา / สาธารณสุข / ทะเบียนราษฎร / สายด่วน) พร้อมคะแนนความมั่นใจ เพื่อจัดคิวลงพื้นที่ |
| สิ่งที่เด็กต้องการมัก **ไม่ได้อยู่ในมือกระทรวงศึกษาฯ** (เงิน เอกสาร สุขภาพ งาน) | **ส่งต่อข้ามหน่วยงาน** พร้อมชื่อผู้รับ นาฬิกา SLA และสถานะความยินยอมตาม PDPA |
| ปลายทางไม่ได้มีแค่ “กลับห้องเรียน” | **เส้นทางโอกาสรายบุคคล 7 เส้นทาง** — กลับโรงเรียน / สกร. / อาชีวะ / เอกชนสอนศาสนาอิสลาม / ทวิภาคี / มีงานทำ / การศึกษาพิเศษ (บวกสถานะ “ยังไม่ตัดสินใจ”) |

และเพราะงานจริงเกิดที่ตำบล จึงมี **แดชบอร์ดตำบล/ชุมชน** เป็นหน่วยที่เล็กที่สุดที่ยังเห็นเด็กเป็นรายคน

## ข้อมูลในต้นแบบ

**ชื่อพื้นที่และรายชื่อโรงเรียนเป็นของจริง ตัวเลขเป็นข้อมูลจำลอง** (deterministic — โหลดกี่ครั้งก็ได้ตัวเลขเดิม)

- **3 จังหวัด · 33 อำเภอ · 250 ตำบล** (ชื่อจริงทั้งหมด)
- **46 โรงเรียนนำร่อง** ตามรายชื่อใน **TOR ภาคผนวก ค** — สพม.ปัตตานี 17 · สพม.ยะลา 12 · สพม.นราธิวาส 17
- พิกัด lon/lat จริงของทุกอำเภอ ฉายลงบนเส้นขอบจังหวัดจริง (`src/data/thailandPaths.ts`)
- 2,685 ระเบียนเด็กนอกระบบ · 900 เด็กในระบบที่ติดตามรายคน (~20 คนต่อโรงเรียนนำร่อง)
- 1,972 แผนโอกาส · 4,739 การส่งต่อ · 900 เคสติดตาม · 36 หน่วยงานร่วม

> **ข้อควรระวังที่ระบุไว้ในโค้ดแล้ว** — TOR ระบุโรงเรียนถึงระดับจังหวัดเท่านั้น ค่า “อำเภอ” ของแต่ละโรงเรียนเป็นการแมป best-effort
> และพิกัดหมุดโรงเรียนคำนวณจากศูนย์กลางอำเภอ ไม่ใช่พิกัดรังวัดจริง — แก้ได้ที่ตารางเดียวใน `src/data/schools.ts`

### ตัวเลขทุกระดับ “นับ” มาจากทะเบียนจริง
ยอดรวมระดับจังหวัด/อำเภอ/ตำบล **ไม่ได้สุ่มขึ้นมาต่างหาก** แต่ roll-up มาจากทะเบียนเด็กรายคน
(`data/oosc.ts` → `data/places.ts`) — กดจาก “เด็กนอกระบบ 82 คน” ลงไป จะเจอชื่อครบ 82 คนจริง

## บทบาทผู้ใช้ (5 บทบาท)

| บทบาท | ใครใช้ | ขอบเขตที่เห็น |
|---|---|---|
| **ผู้บริหาร** | ศอ.บต. · คณะทำงานจังหวัด · นายอำเภอ/ศปก.อำเภอ | ตาม**ขอบเขตของบัญชี** — ทั้งพื้นที่ จชต. / จังหวัดเดียว / อำเภอเดียว |
| **ผู้บริหาร สพฐ.** | สพฐ. ส่วนกลาง (และ สพม. ถ้ากำกับจังหวัด) | ทุกจังหวัด ทุกโรงเรียน และ**นักเรียนรายคน** — ไม่มีงานส่งต่อข้ามหน่วยงานและตำบล |
| **ผู้บริหารสำนักเขต** | สำนักงานเขตพื้นที่การศึกษา | เขตของตน → อำเภอ → โรงเรียน → นักเรียนรายคน (งานเดียวกับ สพฐ. คนละชั้น) |
| **ผอ.สถานศึกษา** | ผู้อำนวยการโรงเรียน | นักเรียนและเคสในสถานศึกษา |
| **ครู / ผู้จัดการรายกรณี** | ครูแนะแนว เจ้าของเคส | เฉพาะเคสที่ตนดูแล |
| **หน่วยงานที่รับส่งต่อ** | พมจ. / สธ. / แรงงาน | เฉพาะเคสที่ถูกส่งต่อมา + นาฬิกา SLA |

ระดับจังหวัด อำเภอ และตำบล **ไม่ใช่บทบาทแยก** — เป็นงานเดียวกันคนละระดับ จึงเก็บเป็น `provinceKey` / `districtKey` บนบัญชีแทน

### กติกาความเป็นส่วนตัว (TOR ๔.๕.๕ + PDPA)
สิทธิ์ตาม**หน้าที่** ไม่ใช่ตาม**ตำแหน่ง** — บังคับที่ `navFor()` ใน `src/auth/roles.ts` ที่เดียว:

```
ผู้บริหารที่ไม่มีจังหวัด/อำเภอกำกับ (ศอ.บต.)  →  7 เมนู   ภาพรวมล้วน ไม่มีชื่อเด็กรายคน
ผู้บริหารที่มีจังหวัดหรืออำเภอกำกับ            →  12 เมนู  เห็นทะเบียน แผน ส่งต่อ และตำบล
ผู้บริหาร สพฐ. (ส่วนกลาง)                       →  13 เมนู  เห็นทั้ง 3 จังหวัดถึงระดับนักเรียนรายคน
ผู้บริหารสำนักเขต                                →  13 เมนู  เมนูเท่า สพฐ. แต่ข้อมูลเหลือเฉพาะเขตของตน
```

**ศูนย์ตัดสินใจ** (`/decision`) เป็นหน้าเฉพาะของสายการศึกษา รวมแผนที่ + ตัวเลข + AI ไว้หน้าเดียว —
สรุปสถานการณ์อัตโนมัติ · จัดลำดับว่าควรลงอำเภอไหนก่อนพร้อมเหตุผล · คาดการณ์ 12 เดือนและจำลองมาตรการ 4 แบบ ·
ถามเป็นภาษาคนแล้วกดลิงก์ไปหน้าที่เกี่ยว **คะแนนและการคาดการณ์คำนวณด้วยสูตรใน `src/lib/decision.ts` ไม่ใช่ AI**
AI ทำหน้าที่เล่าและตอบคำถามเท่านั้น หน้านี้จึงทำงานได้เต็มรูปแบบแม้ยังไม่ได้ใส่ `ANTHROPIC_API_KEY`

**แผนที่อัจฉริยะเชิงพื้นที่** (`/geo`) เป็นหน้าคู่กัน สำหรับไล่ดูเชิงภูมิศาสตร์ —
breadcrumb **ประเทศไทย (นำร่อง จชต.) → จังหวัด → เขตพื้นที่การศึกษา → อำเภอ → โรงเรียน** ·
สลับตัวชี้วัดบนแผนที่ · เปิด/ปิดชั้นโรงเรียนกับชั้นนักเรียน · ตัวกรอง 5 ตัว (ปีการศึกษา · ระดับความเสี่ยง ·
ประเภทสถานศึกษา · ระดับชั้น · สถานะนักเรียน) · พาเนลขวาแสดง KPI แนวโน้ม 12 เดือน สาเหตุหลัก
ช่องถามที่**ซูมแผนที่ไปยังคำตอบ** และข้อเสนอเชิงปฏิบัติ · ด้านล่างจัดอันดับได้ทั้งระดับจังหวัด เขต และสถานศึกษา

ช่องถามจับคู่คำถามกับรายชื่อพื้นที่ในขอบเขตแบบกำหนดได้ (deterministic) แล้วสั่ง drill — ปลายทางบนแผนที่
จึงอธิบายได้เสมอว่าทำไมไปที่นั่น ไม่ได้ปล่อยให้โมเดลเลือกเอง ระดับชั้นกับสถานะนักเรียนกรองที่**ตัวนักเรียน**
จึงมีบรรทัดนับแยกในพาเนล เพราะ KPI สี่ตัวด้านบน roll-up มาจากยอดพื้นที่ซึ่งไม่มีข้อมูลชั้นเรียนหรือสถานะ

> **ข้อจำกัดที่ระบุไว้บนหน้าจอแล้ว** — มีรูปทรงแผนที่จริงถึงระดับ**จังหวัด**เท่านั้น อำเภอและโรงเรียนเป็นหมุดพิกัด
> และไม่มีรูปทรงขอบเขตของ สพท. เขตจึงแสดงเป็น**กลุ่มอำเภอ** ไม่ใช่ polygon · ชั้นนักเรียนรวมเป็นระดับอำเภอเสมอ
> ไม่แสดงที่อยู่รายคนตาม PDPA · กราฟแนวโน้ม 12 เดือนเป็นข้อมูลจำลองแบบคงที่ ไม่ใช่สถิติย้อนหลังจริง

ที่นั่งระดับพื้นที่มีสองที่นั่งและ**เห็นไม่เท่ากัน** ซึ่งไม่ใช่ข้อยกเว้นของ TOR ๔.๕.๕ แต่คือกฎเดียวกันที่ใช้อย่างตรงไปตรงมา —
**ศอ.บต.** เป็นหน่วยประสาน จึงอยู่กับภาพรวมและไม่เห็นชื่อเด็ก ส่วน **สพฐ.** เป็นเจ้าของทะเบียนนักเรียนเอง (DMC ตามข้อ ๔.๓)
จึงเห็นเด็กรายคนได้ทั้งพื้นที่ สิทธิ์ยังเดินตาม*หน้าที่* ไม่ใช่ตาม*ตำแหน่ง*

สพฐ. แยกเป็นบทบาทของตัวเองเพราะ*งาน*ต่างกัน ไม่ใช่ระดับต่างกัน — รับผิดชอบผลการดำเนินงานของโรงเรียนและการพาเด็กกลับเข้าเรียน
ส่วนการส่งต่อไป พมจ./สธ./แรงงาน และโต๊ะประสานระดับตำบลยังเป็นอำนาจของ ศอ.บต. กับทีมพื้นที่
ถ้าใส่ `provinceKey` ให้บัญชี `obec` บทบาทเดิมจะกลายเป็นที่นั่ง **สพม.** ที่ถูกจำกัดเหลือจังหวัดเดียวทันที
(ในชุดข้อมูล TOR หนึ่ง สพม. ตรงกับหนึ่งจังหวัดพอดี จึงไม่ต้องมีคีย์ขอบเขตตัวที่สอง)

พิมพ์ URL ตรงเข้าหน้าที่ไม่มีสิทธิ์จะถูกเด้งกลับหน้าแรก (`RequireAuth`) ส่วนการกรองข้อมูลรายแถวอยู่ที่ `src/auth/scope.ts` ที่เดียว ไม่กระจายในหน้าเพจ

## รันโปรเจกต์

```bash
npm install
npm run dev          # http://localhost:5173
```

โหมดโปรดักชันพร้อม AI ผู้ช่วย (คีย์อยู่ฝั่งเซิร์ฟเวอร์เท่านั้น):

```bash
cp .env.example .env   # ใส่ ANTHROPIC_API_KEY
npm run serve          # build + node server.mjs
```

**หน้า Login** มีการ์ดเดโม 4 ใบ (บทบาทละใบ) **กดแล้วเข้าระบบทันที** และมีลิงก์เข้าเป็น “ผู้บริหารระดับจังหวัด” เพื่อดูมุมมองที่เห็นข้อมูลระดับเคส
ถ้าจะกรอกเอง: อีเมลของบัญชีเดโม + รหัสผ่าน `demo`

|---|---|
