# วิดีโอ PR สำหรับผู้บริหาร (Remotion)

วิดีโอ ~4:02 นาที · 1920×1080 · 30 fps · H.264 + AAC · ไม่มีเสียงบรรยาย มีแต่ข้อความภาษาไทยบนจอ
**เปิดด้วยฉากแอนิเมชันโรงเรียนกลางวัน** (SVG วาดเอง: ฟ้าใสเมฆขาว · สนามหญ้า · เด็กเล่นฟุตบอล · อาคารขาว-ฟ้า หลังคาเทา · ธงชาติ · มะพร้าว · ทางเดินมีกระถางดอกไม้ · ต้นไม้ใหญ่คลุมมุมซ้าย)
แล้ว **ซูมเข้าหน้าต่างห้องเรียน** จอค่อยมืดเป็นโทนห้องเรียน ก่อนตัดเข้าฉากห้องเรียนที่มีเก้าอี้ว่าง (`SchoolScene` ใน `src/story.tsx`)
จากนั้นเล่าเคสจำลองหนึ่งเคสผ่าน **หน้าจอจริง** ตามลำดับ ครู → ผอ.สถานศึกษา → เขตพื้นที่ → ผู้บริหาร สพฐ.
แล้วปิดด้วยข้อเสนอทดลองนำร่องและ QR ไปยังเว็บต้นแบบ

**แต่ละ role เล่าเป็น journey ทีละขั้น** บนหน้าต่างเบราว์เซอร์ที่ **ล็อกอยู่กับที่** (ไม่บินเข้า/ซูมกระโดดทุกฉาก)
มี **เคอร์เซอร์เดินไปกดปุ่มจริง** แล้วหน้าจอ crossfade ไปขั้นถัดไป — ให้คนดูเห็น *วิธีใช้งานระบบ* ไม่ใช่ภาพนิ่งแว้บไปมา
(โจทย์จาก CEO: ต้องเห็นขั้นตอนการเล่นระบบของแต่ละ role) ตัวนับ “ขั้น N/ทั้งหมด” อยู่มุมคำบรรยาย

**บทครูเน้นผู้ช่วย AI** (โจทย์จาก CEO รอบสอง): มี 2 ขั้นที่โฟกัส AI โดยเฉพาะ —
“แนวทางที่อาจช่วยได้” (`t6-ai-rec`: AI เสนอวิธีช่วยเป็นขั้น พร้อมเหตุผลจากข้อมูลเด็กรายคน · ตรรกะอยู่ที่ `src/lib/recommend.ts`)
และ “ถาม AI” (`t7-ai-ask`: ถามต่อได้ ทำไมเสี่ยง/ช่วยอะไรไปแล้ว/ควรส่งต่อใคร — AI ตอบจากข้อมูลเคส)

| ไฟล์ | คืออะไร |

## สร้างใหม่ตั้งแต่ต้น

```bash
# 1) ที่ราก repo: เปิดแอป (สคริปต์จับภาพใช้ http://localhost:5173)
npm run dev

# 2) ในโฟลเดอร์ video/
npm install
npm run capture          # จับภาพหน้าจอจริงตาม workflow ครู → ผอ. → เขต → สพฐ. → กลับถึงครู
npm run prepare-assets   # แผนที่ · QR · ดนตรี · ไฟล์ SRT (อ่านจาก timeline.mjs)
npm run studio           # ดูและปรับในเบราว์เซอร์ (ไม่บังคับ)
npm run render           # → out/sbp-pr-film.mp4
```

ต้องมี Google Chrome ที่ `C:/Program Files/Google/Chrome/Application/chrome.exe`
(ตั้งไว้ใน `remotion.config.ts` และ `scripts/lib.mjs`) ไม่ต้องติดตั้ง ffmpeg เพราะ Remotion มีมาให้

## สิ่งที่สคริปต์จับภาพทำ และทำไม

- **ทำ workflow จริงในแอป** ไม่ได้แต่งภาพ: ครูบันทึกเยี่ยมบ้านและส่งคำขอถึง ผอ. → ผอ. อนุมัติและยกระดับถึงเขต →
  เขตตัดสินใจและส่งกลับ ผอ. → ครูเห็นงานถัดไป ทุกขั้นอยู่ใน browser context เดียว คำขอจึงไปถึงอีกบทบาทจริง
- **บันทึกพิกัดปุ่มที่แต่ละขั้นต้องกด** ลง `src/boxes.json` (`scrollIntoViewIfNeeded` ก่อน เพื่อให้ปุ่มในแผง drawer
  เลื่อนขึ้นมาอยู่ในกรอบภาพ) แล้วถ่ายภาพ *ในสภาพที่เลื่อนแล้ว* เคอร์เซอร์ในวิดีโอจึงไปกดตรงปุ่มในภาพพอดี
  ถ้าปุ่มเปลี่ยนตำแหน่ง/ข้อความ ให้ `npm run capture` ใหม่ (รันทั้งชุดจะล้าง localStorage เริ่มจาก seed สะอาด ไม่ให้คำขอซ้ำ)
- **แทนชื่อด้วยนามสมมติก่อนถ่าย**: ชื่อเด็กในข้อมูลจำลองเป็น "นักเรียน ก., ข., …" (เด็กตัวเดินเรื่อง = ก. เสมอ)
  และชื่อโรงเรียนจริง 46 แห่งตามภาคผนวก TOR เป็น "โรงเรียนสาธิต 1–46" เพราะตัวเลขความเสี่ยงของแต่ละโรงเรียนเป็นข้อมูลจำลอง
  ชื่อบุคลากรและบัญชีสาธิตไม่ถูกแทน เพราะเป็นตัวละครสมมติอยู่แล้ว
- ชื่อโรงเรียนบางแห่งซ้ำกับชื่อจังหวัด (เช่น "นราธิวาส") ชื่อแบบไม่มีคำนำหน้าจึงไม่ถูกแทน ไม่อย่างนั้นชื่อจังหวัดจะหายไปจากหน้า สพฐ.

## ก่อนนำไปฉาย

- **QR และลิงก์ท้ายเรื่องชี้ไปที่ GitHub Pages** (`DEMO_URL` ใน `src/timeline.mjs`) ซึ่งเป็นเว็บ static ผู้ช่วย AI จึงตอบจากข้อมูลในระบบเท่านั้น
  เว็บ deploy จาก `main` ถ้า `main` ยังไม่มีหน้าจอบางหน้าที่อยู่ในวิดีโอ ผู้ที่สแกนจะเห็นไม่ตรงกัน ให้ merge และรอ deploy ก่อนวันนำเสนอ
  ถ้าจะเปลี่ยนลิงก์: แก้ `DEMO_URL` แล้วรัน `node scripts/qr.mjs && npm run render`
- ภาพหน้าจอถ่ายจาก branch ที่ checkout อยู่ตอนรัน `capture` ถ้าหน้าจอในแอปเปลี่ยน ให้จับภาพใหม่ และตรวจกรอบไฮไลต์ (`focus`/`mark` ใน timeline)
- **ดนตรีประกอบ** เพลงยาว 2:29 แต่วิดีโอยาว 3:51 จึงเล่นสองรอบ (รอบแรกจางออกที่ 1:21 แล้วเริ่มใหม่ตอนขึ้นบท ผอ.) และใส่เครดิตไว้ท้ายเรื่องแล้ว
