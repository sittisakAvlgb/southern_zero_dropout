# เส้นทางโอกาสรายบุคคล — Case Workspace ของครู

> เอกสารประกอบการรื้อหน้า `/plan` ตาม redesign brief (ต.ค. 2026)
> **Clickable Prototype คือแอปจริง** — `npm run dev` → ล็อกอิน `teacher@zerodropout.go.th` / `demo` → เมนู "เส้นทางโอกาสรายบุคคล"

หลักที่ยึดตลอด: **"ครูเข้ามาเพื่อช่วยนักเรียน ไม่ได้เข้ามาเพื่อดู Dashboard"**

## 1. UX Flow

```
                 หน้าแรกครู (เคสของฉัน)
                 การ์ดเลขา AI ─ [สร้างแผน] / [เปิดแผน]
                          │  /plan?child=ID
                          ▼
┌──────────────── เส้นทางโอกาสรายบุคคล ────────────────┐
│ AI: N แผน · N วันนี้ · N คนเสี่ยงแต่ยังไม่มีแผน         │
│ [เปิดเคสแรก]                                        │
│ 🔴 วันนี้ · 🟠 ภายใน 3 วัน · 🟡 ตามกำหนด · 🟢 ดีขึ้น      │
│ ○ เสี่ยงสูงแต่ยังไม่มีแผน ─ [สร้างแผน]                  │
└──────────┬─────────────────────────────┬──────────────┘
           │ เปิดเคส                      │ สร้างแผน
           ▼                              ▼
   ┌── Case Workspace ──┐        ┌── สร้างแผน ──────────┐
   │ AI สรุป             │        │ 1 วางแผน (กรอกให้แล้ว) │
   │ ขั้นตอนถัดไป ◀ เด่นสุด │        │ 2 AI Recommended Path │
   │ milestone 7 ขั้น     │        │   [เริ่มดำเนินการ] ─────┼─▶ Case Workspace
   │ ขั้นในแผน + เจ้าภาพ   │        └──────────────────────┘
   │ timeline            │
   │ [บันทึก][นัด][AI]    │ ← แถบติดก้นจอ
   └─┬───┬───┬───┬───┬──┘
     │   │   │   │   └─ ประเมินก่อนปิด → [ปิดเคส ×2] / [ติดตามต่อ 14 วัน]
     │   │   │   └───── ส่งต่อ: หน่วยงาน → เหตุผล → ข้อมูล (PDPA) → ยืนยัน → รอรับเรื่อง
     │   │   └───────── ติดอุปสรรค → AI เสนอทางเลือก → บันทึก / ส่งต่อ
     │   └───────────── นัดติดตาม → ขึ้นเป็น "สิ่งที่ต้องทำวันนี้" ในหน้าแรกเมื่อถึงวัน
     └───────────────── บันทึกการช่วยเหลือ → ติ๊กขั้นที่ตรงกันในแผนให้เอง
```

Core flow ตาม brief: **วางแผน → แนะนำ → ลงมือทำ → ติดตาม → ปิดเคส**

## 2. Information Architecture

| ลำดับบนจอ | หน้ารายการ | หน้าเคส |
|---|---|---|
| 1. สิ่งที่ต้องทำตอนนี้ | การ์ด AI: ตัวเลข + insight + ปุ่มเดียว | **ขั้นตอนถัดไป** พร้อมเหตุผล ผู้รับผิดชอบ กำหนด |
| 2. เคสเร่งด่วน | กลุ่ม 🔴 → 🟢 เรียงตามความเร่งด่วน ไม่ใช่ตามชื่อ | ป้ายความเร่งด่วนบนหัว |
| 3. AI Recommendation | insight บนการ์ด AI | สรุปจาก AI · แผ่น "AI แนะนำ" |
| 4. แผนและ Milestone | จุด 7 จุดบนแต่ละแถว | milestone 7 ขั้น + ขั้นในแผน |
| 5. Timeline | — | "ที่ผ่านมาเกิดอะไรขึ้นแล้วบ้าง" |
| 6. รายละเอียด | — | เหตุผลของเส้นทาง · ครอบครัว · PDPA |
| 7. สถิติ | พับไว้ท้ายหน้า | — |

NUMBER → INSIGHT → ACTION → DETAIL:
`3 แผน · 1 วันนี้` → `1 ใน 1 เคสเร่งด่วนรอหน่วยงานภายนอกอยู่` → `[เปิดเคสแรก]` → หน้าเคส

## 3. ความเร่งด่วน

| ระดับ | เงื่อนไข (`buildCase` ใน `src/lib/planOps.ts`) |
|---|---|
| 🔴 ต้องดำเนินการวันนี้ | มีขั้นติดขัด · ขั้นปัจจุบันเลยกำหนด · นัดติดตามถึงวัน · เด็กอยู่ระดับวิกฤต |
| 🟢 สถานการณ์ดีขึ้น | เข้าเกณฑ์ปิดเคสแล้ว |
| 🟠 ภายใน 3 วัน | ขั้นปัจจุบันครบกำหนดใน 3 วัน · ครอบครัวยังไม่เห็นชอบ |
| 🟡 ติดตามตามกำหนด | ที่เหลือ |

## 4. ขั้นตอนถัดไป (Next Best Action)

เลือกตามลำดับนี้ — ข้อแรกที่เข้าเงื่อนไขชนะ:

| ลำดับ | สถานการณ์ | ขั้นถัดไป | ปุ่มหลัก |
|---|---|---|---|
| 1 | มีขั้นติดขัด | ปลดล็อกขั้น | ทวงถามเจ้าภาพ / ติดอุปสรรค / ส่งต่อ |
| 2 | เข้าเกณฑ์ปิดเคส | ประเมินผลและปิดเคส | ประเมินผลก่อนปิดเคส |
| 3 | ทำครบทุกขั้นแต่ยังไม่ผ่านเกณฑ์ | ประเมินผลหลังช่วยเหลือ | ประเมินผลก่อนปิดเคส |
| 4 | ครอบครัวยังไม่เห็นชอบ | ขอความเห็นชอบ | บันทึกว่าครอบครัวเห็นชอบ |
| 5 | ขั้นปัจจุบันเป็นงานของโรงเรียน | ทำขั้นนั้น | ทำขั้นนี้เสร็จแล้ว |
| 6 | ขั้นปัจจุบันอยู่กับหน่วยงานภายนอก | รอหน่วยงาน | ทวงถามเจ้าภาพ |

## 5. ผู้รับผิดชอบ

ทุกขั้นมีเจ้าภาพที่ระบุตายตัว (`STEPS_BY_PATHWAY` ใน `src/data/plans.ts`)
**"คุณ (โรงเรียน)"** = งานของครูเอง ไม่ต้องรอใคร ที่เหลือคือหน่วยงานภายนอก

หน่วยงานที่แนะนำตอนส่งต่อเรียงตาม **กลุ่มรหัสสาเหตุ สพฐ.** ของเด็ก
(3xx ครอบครัว → พมจ./ท้องถิ่น · 2xx สุขภาพ → สาธารณสุข ฯลฯ) ดู `src/data/dropReasons.ts`

## 6. เกณฑ์ปิดเคส

ปิดได้เมื่อผ่าน 3 ข้อแรกทั้งหมด (นิยามเดียวกับ `closability()` ที่หน้าแรกใช้):

1. กลับมาเรียนสม่ำเสมอ — มาเรียน ≥ 80% และขาดติดกันไม่เกิน 2 วัน
2. ความเสี่ยงลดลง — ลด ≥ 8 คะแนนใน 8 สัปดาห์ **และ** ต่ำกว่า 70
3. ติดต่อผู้ปกครองได้ตามปกติ

ข้อ 4 "ยังมีปัจจัยเสี่ยงค้างอยู่หรือไม่" เป็น**ข้อเตือน ไม่ใช่ข้อห้าม** —
ภาระครอบครัวคิดจากรายได้เป็นหลัก ถ้าใช้เป็นข้อห้าม เด็กจากครอบครัวยากจน
จะปิดเคสไม่ได้ตลอดไปแม้กลับมาเรียน 100% แล้ว

ระบบเสนอ **ครูเป็นคนกดปิดเสมอ** และต้องกดสองครั้ง

## 7. UX States

| สถานะ | อยู่ที่ไหน |
|---|---|
| Loading / Skeleton | การ์ด AI และรายการเคส ตอนเปิดหน้า |
| AI Processing | แผ่น "AI แนะนำ" — "AI กำลังวิเคราะห์ข้อมูลของเด็กคนนี้…" |
| Empty | ไม่มีแผนและไม่มีเด็กเสี่ยง → ข้อความอธิบายว่าจะขึ้นเมื่อไร |
| No urgent | การ์ด AI: "ไม่มีเคสเร่งด่วนวันนี้ ทุกแผนยังอยู่ในกำหนด" |
| Error (validation) | ส่งต่อ: ไม่เลือกหน่วยงาน · เหตุผลสั้นเกินไป |
| Disabled | บันทึกการช่วยเหลือ: กดไม่ได้จนกว่าจะเลือกผลลัพธ์ |
| Success | toast ทุกการบันทึก · หน้า "ส่งต่อแล้ว" · หน้า "ปิดเคสแล้ว" |
| Warning | ข้อมูล PDPA ล็อกเมื่อยังไม่มีความยินยอม · ภาระครอบครัวค้างตอนปิด |
| Read-only | บัญชีกำกับดูแล (`canWorkCases` = false) ไม่เห็นปุ่มเขียนใด ๆ |

> Offline ยังไม่ได้ทำ — บันทึกทั้งหมดอยู่ใน localStorage ของเครื่องจึงใช้งานได้
> แม้เน็ตหลุด แต่ยังไม่มีการซิงก์กลับเซิร์ฟเวอร์ (ระบบนี้ยังไม่มี backend)

## 8. ทดสอบตาม 3 Scenario

**Scenario 1 — พบเด็กเสี่ยงใหม่**
หน้าแรก → การ์ดเลขา → [สร้างแผน] → ข้อมูลกรอกมาแล้ว → [ถัดไป · ให้ AI แนะนำ]
→ AI Recommended Path → [เริ่มดำเนินการ] → เข้าเคสใหม่ → [บันทึกว่าครอบครัวเห็นชอบ]

**Scenario 2 — ติดตามเคสเดิม**
/plan → 🔴 เคสวันนี้ → เปิดเคส → อ่าน timeline → [บันทึกการช่วยเหลือ] → เยี่ยมบ้าน
→ ขั้น "ลงเยี่ยมบ้าน" ติ๊กให้เอง → [AI แนะนำ] ขั้นถัดไป → [นัดติดตาม]

**Scenario 3 — สถานการณ์ดีขึ้น**
/plan → 🟢 ดีขึ้น → เปิดเคส → [ประเมินผลก่อนปิดเคส] → ✓✓✓ + AI สรุป
→ [ปิดเคส] → [ยืนยัน] → ย้ายไปอยู่ "ปิดเคสแล้ว"

## 10. ยังไม่ได้ทำ

- **ส่งต่อจากเคสยังไม่ขึ้นในหน้า "ส่งต่อข้ามหน่วยงาน"** — บันทึกอยู่ในเคสและ timeline
  แต่หน้าส่งต่ออ่านจากข้อมูลตั้งต้นชุดเดียว ต้องรวมสองแหล่งเข้าด้วยกัน
- **หลักฐาน/เอกสารแนบ** ใน action (brief ข้อ 4) — ต้องมีที่เก็บไฟล์
- **Reminder** แบบแจ้งเตือน — ตอนนี้นัดติดตามขึ้นในหน้าแรกเมื่อถึงวัน แต่ไม่มี push
- **หน้าภาพรวมของ ผอ./เขต** ยังเป็นแบบเดิม (แก้แค่บั๊กข้อมูลและการบันทึก)
- **เด็กชื่อซ้ำกัน** ทำให้ข้อมูลเคสจับคู่ผิดคน — แยกเป็นงานไว้แล้ว
