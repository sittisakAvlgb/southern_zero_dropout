# ศูนย์ติดตามการช่วยเหลือ (ครู)

> **"ครูไม่ควรเปิดระบบเพื่อเช็กว่าเคสอยู่สถานะอะไร แต่ต้องเปิดแล้วรู้ทันทีว่าควรทำอะไรต่อ"**

หน้า `/intervention` ของบัญชีครูเปิด `TeacherFollowUpCenter` บทบาทอื่นยังเห็นหน้ากำกับดูแลเดิม (`OversightTracking`)

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `src/lib/followOps.ts` | ตรรกะทั้งหมด: เหตุผลที่ต้องดู · ลำดับความสำคัญ · สุขภาพเคส · SLA · ขั้นถัดไป · AI สรุป 4 ช่อง · ตัวกรอง · timeline |
| `src/lib/caseLog.ts` | `lastLoggedMap()` นิยามเดียวของ "อัปเดตล่าสุด" (หน้าเคสของฉันใช้ด้วย) · ฟิลด์นัด `followUpTime/Method/Owner` · `escalation` |
| `src/components/followup/TeacherFollowUpCenter.tsx` | หน้ารายการ |
| `src/components/followup/FollowCaseDetail.tsx` | ลิ้นชักรายละเอียด + แผ่นงาน (บันทึกผล · นัด · ปิด · เปิดใหม่ · Escalate · ถาม AI) |

## Flow

```
วันนี้ต้องติดตาม N เคส → เลือกเคส (หรือกดปุ่มหลักบนการ์ดได้เลย)
→ AI สรุป → ขั้นถัดไป → ลงมือ → เลือกผลลัพธ์ → Timeline อัปเดต
→ ถามต่อทันที: นัดติดตามครั้งถัดไป / ส่งต่อ → หรือประเมินเพื่อปิด → ปิด → (เปิดใหม่ได้ ประวัติเดิมอยู่)
```

## IA ของหน้า

1. **สิ่งที่ต้องทำวันนี้** (เด่นที่สุด) — "วันนี้ต้องติดตาม N เคส" · ข้อสังเกตเดียวจาก AI ว่างานวันนี้ส่วนใหญ่ติดที่อะไร · ✓ ทำแล้ววันนี้ · [เริ่มติดตามเคสแรก]
2. **ตัวกรองด่วน** พร้อมตัวเลข — วันนี้ · เกิน SLA · เสี่ยงสูง · ไม่มีการอัปเดต · รอผู้ปกครอง · รอหน่วยงาน · ใกล้ปิดเคส · เคสของฉันทั้งหมด
   > ตัวเลขอยู่ในตัวกรองที่เดียว ไม่ทำการ์ดตัวเลขอีกชุด — เคยโดนติว่าหน้าครู "ซ้ำ ๆ"
3. **รายการจัดกลุ่มตามเหตุผล** (🔴 วิกฤต · 🔴 เกิน SLA · 🟠 ความเสี่ยงกลับมาหลังปิด · 🟠 เพิ่มขึ้น · 🟡 ครบกำหนด · 🟡 ไม่อัปเดตนาน · 🔵 รอหน่วยงาน · 🟢 ใกล้ปิด)
4. ทำแล้ววันนี้ / ปิดเคสแล้ว — พับไว้

การ์ดเคส: ชื่อ · ความเสี่ยง · สุขภาพเคส · **"ต้องดูวันนี้ เพราะ…"** · อัปเดตล่าสุด · SLA เป็นข้อความ · **ถัดไป** · ปุ่มหลักปุ่มเดียว + [ดูเคส]

## รายละเอียดเคส (บนลงล่าง)

1. หัว: ชื่อ · ความเสี่ยง · สุขภาพเคส · SLA
2. **สถานะวันนี้** — เหตุผล · อัปเดตล่าสุด · ผู้รับผิดชอบ · นัดครั้งถัดไป · ยกระดับแล้วหรือยัง
3. **AI สรุป** — สถานการณ์ / ความเสี่ยง / เปลี่ยนแปลง / แนะนำ (ขึ้น "AI กำลังสรุปข้อมูลล่าสุด…" ก่อน) · [ทำตามคำแนะนำ] [ถาม AI เพิ่มเติม]
4. **ขั้นถัดไป** + เหตุผล + ปุ่มหลัก + ปุ่มรอง (ไม่เกิน 2)
5. **บันทึกสั้น** — พิมพ์บรรทัดเดียว เข้า Timeline ทันที
6. **Timeline** — "ที่ผ่านมาเกิดอะไรขึ้นแล้ว": บันทึกครู + ระเบียน + การส่งต่อ + จุดที่ระดับความเสี่ยงเปลี่ยน
7. **Pipeline** — "ตอนนี้เคสอยู่ขั้นไหน" (แยกจาก Timeline ตาม brief)
8. ลิงก์: ข้อมูลเด็ก · แผนโอกาส · การส่งต่อ · ประวัติทั้งหมด

แถบติดล่าง: [บันทึกผล] [นัดติดตาม] [ถาม AI]

## กติกา

| เรื่อง | กติกา |
|---|---|
| SLA ติดตาม | 7 วันนับจากการลงมือครั้งล่าสุด (`FOLLOW_UP_SLA_DAYS`) · ไม่อัปเดต ≥ 5 วัน = "นาน" |
| อัปเดตล่าสุด | บันทึก + ติ๊กขั้นในแผน **ไม่นับ** การนัดหรือ Escalate อย่างเดียว — ไม่งั้นเคลียร์ SLA ได้โดยไม่เคยติดต่อเด็ก |
| ลำดับ | วิกฤต → เกิน SLA → ความเสี่ยงเพิ่ม (+5 ใน 8 สัปดาห์) → ครบกำหนดนัด / การส่งต่อรอครู → ไม่อัปเดตนาน → รอหน่วยงาน → ปกติ → ใกล้ปิด |
| สุขภาพเคส | 🔴 วิกฤต หรือเกิน SLA + เสี่ยงสูง · 🟠 เกิน SLA / ไม่อัปเดต / การส่งต่อค้าง / ไม่มีเจ้าของ · 🟡 เพิ่มขึ้น / ถึงนัด / เสี่ยงสูง · 🟢 อื่น ๆ (สูตรไม่แสดงให้ครูเห็น) |
| ขั้นถัดไป | การส่งต่อที่รอครู → หน่วยงานเกิน SLA → ถึงนัดเยี่ยมบ้าน → ผู้ปกครอง (โทรไม่ติดแล้ว → นัดเยี่ยมบ้าน · นัดแล้ว → รอตามนัด) → เยี่ยมบ้าน (เสี่ยงสูง) → ดีขึ้นแต่การส่งต่อยังเปิด → ประเมินปิด → ส่งต่อ → สร้างแผน → ประเมินซ้ำ → ตามนัด → ตามรอบ |
| ผลลัพธ์ | ทุก action ถามผลทันที (ติดต่อได้ / ไม่ได้ / นัดหมาย / ขอเวลา / พบปัญหาใหม่ / ต้องส่งต่อ ฯลฯ) และอัปเดตสถานะผู้ปกครอง/เยี่ยมบ้านของเด็กด้วย |
| Escalate | ครูเลือกเอง (หัวหน้างานแนะแนว / ผอ. / เปลี่ยนผู้รับผิดชอบ / ส่งต่อ) บันทึกเหตุผลใน Timeline — ไม่มีอัตโนมัติ |
| ปิดเคส | ต้องผ่านเกณฑ์ `closability` ครบ + ไม่มีการส่งต่อเปิดอยู่ + ครูยืนยันว่าคุยกับครอบครัวแล้ว |
| เปิดใหม่ | เสนอเองเมื่อความเสี่ยงกลับมา (สูง หรือ +5) · กดเองได้เสมอ · ประวัติเดิมอยู่ในเคสเดียวกัน |
| ถาม AI | คำถามสำเร็จรูป 6 ข้อ ตอบจากข้อมูลของเด็กในเครื่อง — ใช้ได้ทั้ง Netlify และ GitHub Pages |

## สถานะ

Loading (skeleton) · AI processing ("AI กำลังสรุปข้อมูลล่าสุด…") · Empty ("ยังไม่มีเคสที่ต้องติดตาม") · วันนี้ว่าง ("🎉 เยี่ยมมาก วันนี้ไม่มีเคสเร่งด่วน") · Error ("ไม่สามารถโหลดข้อมูลเคสได้" + ลองอีกครั้ง) · Success ("✓ บันทึกการติดตามแล้ว") · Offline (แถบแจ้ง — บันทึกได้ เก็บในเครื่อง)

## Scenario ที่ทดสอบแล้ว

1. **งานวันนี้** — เริ่มเคสแรก → AI สรุป → [บันทึกการติดต่อ] → "ติดต่อไม่ได้" → สำเร็จ → นัดเยี่ยมบ้าน 3 วัน → ขั้นถัดไปเปลี่ยนเป็น "รอเยี่ยมบ้านตามนัด" → Timeline มีทั้งสองรายการ
2. **เกิน SLA** — เปิดเคส → เหตุผล "เกิน SLA 15 วัน" → Escalate แจ้ง ผอ. → สถานะ "ยกระดับแล้ว" + Timeline · SLA ยังไม่หายจนกว่าจะติดต่อจริง
3. **เคสดีขึ้น** — AI: "ความเสี่ยงลดจากวิกฤตเป็นเฝ้าระวัง (−43)" → ประเมินเพื่อปิด (ครบทุกข้อ + ครูยืนยัน) → ปิด → เปิดเคสอีกครั้ง → ประวัติเดิมยังอยู่

ทดสอบเพิ่ม: 375px ไม่ล้นจอ · แถบติดล่าง · ถาม AI · หน้าเคสของฉันใช้ `lastLoggedMap` ตัวเดียวกันแล้วยังทำงาน

## ข้อจำกัดที่รู้

- ข้อมูลตั้งต้นบางเคสขั้นใน pipeline ไม่ตรงกับ timeline (เช่น ขั้น "แจ้งเตือนแล้ว" แต่ timeline มี "ครูรับเคส") — เป็นข้อมูล seed ไม่ใช่ตรรกะหน้า
- เคสเชื่อมกับเด็กด้วยชื่อ (เหมือนหน้าเคสของฉัน) เด็กชื่อซ้ำอาจได้ระเบียนผิดคน — มีงานแยกไว้แล้ว
- การเตือนนัดแสดงในแอปเท่านั้น ยังไม่มี push / LINE
