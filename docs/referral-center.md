# ศูนย์ส่งต่อเคสข้ามหน่วยงาน (ครู)

> **"การส่งต่อไม่ใช่การโยนเคส แต่คือการส่งมอบความรับผิดชอบแบบติดตามได้"**
>
> ทุกจอต้องตอบได้ภายในไม่กี่วินาทีว่า **เรื่องอยู่ที่ใคร · เกินกำหนดไหม · ต้องทำอะไรต่อ**

หน้า `/referral` ของบัญชีครูเปิด `TeacherReferralCenter` ส่วนบทบาทอื่นยังเห็นหน้ากำกับดูแลเดิม
(`OversightReferrals` ใน `src/pages/Referrals.tsx`)

## ไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `src/lib/refOps.ts` | ตรรกะทั้งหมด: ขั้น · SLA (ชั่วโมง) · escalation · กลุ่มความเร่งด่วน · ขั้นถัดไป · ความพร้อม · ความยินยอม · timeline ข้ามหน่วยงาน |
| `src/lib/caseLog.ts` | บันทึกถาวร: `refs` (การส่งต่อที่ครูสร้าง) · `refEvents` (เหตุการณ์มีเวลาประทับ) · `consents` (ความยินยอมเต็มรูปแบบ) |
| `src/components/referrals/useRefCases.ts` | รวมข้อมูลตั้งต้น + ที่ครูสร้าง + ที่ส่งจากหน้าเคสรุ่นเก่า (`entry.referral`) เป็น `RefCase[]` ชุดเดียว |
| `src/components/referrals/TeacherReferralCenter.tsx` | หน้ารายการ |
| `src/components/referrals/ReferralDetail.tsx` | ลิ้นชักรายละเอียด + แผ่นงานของปุ่มด่วน + ตัวจำลองฝั่งหน่วยงาน |
| `src/components/referrals/CreateReferral.tsx` | ขั้นตอนสร้างการส่งต่อ + ฟอร์มความยินยอม (ใช้ทั้งที่หน้านี้และในเคสของเส้นทางโอกาส) |

หน้าจอไม่ตัดสินใจเอง — ทุกอย่างที่ว่า "ตอนนี้ต้องทำอะไร" มาจาก `buildRefCase()`

## Flow หลัก

```
ระบุปัญหา → AI แนะนำหน่วยงาน → ตรวจความพร้อม → ความยินยอม (PDPA)
→ ดูข้อมูลที่จะส่งจริง + รูปแบบส่งมอบ A/B → ยืนยัน → ส่งสำเร็จ
→ ปลายทางได้รับ → เปิดดู → รับเคส (มีเจ้าหน้าที่) → ดำเนินการ → เสร็จ → ส่งผลกลับ
→ ครูประเมิน → ปิด / ติดตามต่อ / ส่งต่อหน่วยงานอื่นเพิ่ม
```

ทางแยก: ปลายทาง **ขอข้อมูลเพิ่ม** (นาฬิกาหยุด) · **ไม่รับเรื่อง** (ส่งกลับ) · **เกิน SLA** (เตือน → Escalate → เปลี่ยนหน่วยงาน)

## IA ของหน้า

1. **NUMBER → INSIGHT → ACTION** — "N การส่งต่อที่ยังเปิด · X เกิน SLA · Y ใกล้เกิน" → ประโยคเดียวว่าหมายความว่าอะไร → ปุ่มเปิดรายการแรก
2. **ตัวกรองตามกลุ่ม** — ชื่อกลุ่มพร้อมตัวเลขเสมอ ไม่ใช้สีอย่างเดียว
3. **รายการจัดกลุ่มตามเด็ก** — เด็กหนึ่งคนส่งหลายหน่วยงานได้แต่เป็นเคสเดียว การ์ดเดียวต่อเด็ก แต่ละบรรทัดบอก กลุ่ม · ด้าน → หน่วยงาน · **ถัดไป** · SLA เป็นข้อความ
4. **ควรพิจารณาส่งต่อ** — เสี่ยงสูง + สาเหตุอยู่นอกอำนาจโรงเรียน (`needsAgency`) + ยังไม่มีการส่งต่อที่เปิดอยู่
5. **เสร็จแล้ว** — พับไว้

ลำดับความเร่งด่วน (`BUCKET_META.rank`):
เกิน SLA → ใกล้เกิน → ถูกส่งกลับ → ส่งผลกลับรอประเมิน → รอความยินยอม → รอรับเรื่อง → หน่วยงานขอข้อมูล → กำลังดำเนินการ → เสร็จ

> "ถูกส่งกลับ" กับ "ส่งผลกลับรอประเมิน" ไม่มีใน brief — เพิ่มเพราะลูกบอลกลับมาอยู่ที่ครูแต่ไม่มีนาฬิกา SLA เตือน ถ้าไม่ดันขึ้นจะค้างเงียบ

## หน้ารายละเอียด (ลำดับบนลงล่าง)

1. **ขั้นถัดไป** + ปุ่มด่วนเฉพาะที่เกี่ยวกับสถานะนี้ (ไม่เกิน 2 ปุ่ม)
2. **SLA** — "เหลือเวลา 4 ชั่วโมง" / "เกิน SLA 26 ชั่วโมง" + กติกา + ระดับ escalate ที่ทำไปแล้ว
3. ผลที่หน่วยงานส่งกลับ (ถ้ามี)
4. **สถานะการรับเรื่อง** — 8 ขั้น ทุกขั้นมีเวลาประทับ
5. **ใครรับผิดชอบอะไร** — Case Owner · ผู้รับผิดชอบการส่งต่อ · หน่วยงานผู้รับ · เจ้าหน้าที่ · รูปแบบ A/B
6. **ความยินยอม** — ใคร · วิธี · ขอบเขต · หน่วยงาน · วัตถุประสงค์ · หมดอายุ · หลักฐาน
7. **ข้อมูลที่หน่วยงานเห็น** — ตัวอย่างข้อมูลจริงที่ส่ง ไม่ใช่แค่ชื่อหมวด
8. การส่งต่อหน่วยงานอื่นของเด็กคนเดียวกัน
9. **Timeline ข้ามหน่วยงาน** — โรงเรียน / หน่วยงาน / ระบบ ในเส้นเดียว
10. 🧪 จำลองฝั่งหน่วยงานผู้รับ (เดโมเท่านั้น พับไว้)

## กติกา

| เรื่อง | กติกา |
|---|---|
| SLA รับเรื่อง | 24 ชม. · เด็กวิกฤต 12 ชม. · คุ้มครองเด็ก 8 ชม. (`acceptSlaHours`) |
| SLA ดำเนินการ | `NEED_SLA[need]` วันหลังรับเคส |
| ใกล้เกิน | เหลือ ≤ 25% ของ SLA รับเรื่อง / ≤ 48 ชม. ของ SLA ดำเนินการ |
| Escalation | เกิน SLA = ระดับ 1 (แจ้งเตือน) · ค้าง > 48 ชม. หลังส่ง = ระดับ 2 (หัวหน้าหน่วยงาน) · > 72 ชม. = ระดับ 3 (เปลี่ยนหน่วยงาน) · ทำแล้วขั้นถัดไปเปลี่ยนเป็น "รอตอบรับ" ไม่สั่งซ้ำ |
| ความยินยอม | ✓ ยินยอมแล้ว · ⏳ หมดอายุใน ≤ 30 วัน · ⚠ กำลังรอ · ✕ ไม่มี/ไม่ยินยอม/หมดอายุ — ไม่มีความยินยอม **ส่งไม่ได้** บันทึกเป็นร่างได้ |
| ข้อมูลที่ส่ง | เลือกได้เฉพาะในขอบเขตความยินยอม ข้อมูลพื้นฐานส่งเสมอ |
| ความพร้อม | ต้องมี: สรุปปัญหา ≥ 12 ตัวอักษร · ความยินยอม — ควรมี: ติดต่อผู้ปกครองได้ · ประวัติการช่วยเหลือ |
| สิทธิ์ | ปุ่มทั้งหมดอยู่หลัง `canWorkCases()` · ข้อมูลอ่านผ่าน `useScopedData()` |
| เวลาประทับ | **ห้ามประทับเวลาอนาคต** — เหตุการณ์ที่ครูกดตามมาจะเรียงก่อนและถูกกลืน (เคยเป็นบั๊กสองครั้ง) |

## สถานะของหน้าจอ

- **Loading** — skeleton 450ms
- **Empty** — "ยังไม่มีการส่งต่อในความดูแลของคุณ" + วิธีเริ่ม
- **ไม่มีค้าง** — "✓ ไม่มีการส่งต่อที่ค้างอยู่"
- **กำลังส่ง** — spinner + "กำลังส่งเรื่องถึง …"
- **Error** — ออฟไลน์: "ไม่สามารถส่งข้อมูลได้ กรุณาลองใหม่" ข้อมูลที่กรอกยังอยู่ + ลองอีกครั้ง
- **Success** — "ส่งต่อสำเร็จ และหน่วยงานได้รับแจ้งแล้ว" + SLA + [ดูการส่งต่อนี้]
- **ร่าง** — "บันทึกเป็นร่างแล้ว — ยังไม่ได้ส่ง"

## 4 scenario ที่ทดสอบแล้ว

1. **ส่งต่อใหม่** — ควรพิจารณาส่งต่อ → ส่งต่อ → AI เลือกด้านจากรหัสสาเหตุ สพฐ. → [เลือกหน่วยงานนี้] → พร้อมส่ง → ความยินยอม → ข้อมูลที่ส่ง → ยืนยัน → สำเร็จ
2. **ปลายทางรับเรื่อง** — ตัวจำลอง: เปิดดู → รับเคส + เจ้าหน้าที่ → เริ่มดำเนินการ — แถบการรับเรื่องและ "ขั้นถัดไป" เปลี่ยนทุกขั้น
3. **ใกล้/เกิน SLA** — ⏩ +20 ชม. → "ใกล้เกิน SLA เหลือ 4 ชั่วโมง" [ส่งการแจ้งเตือน][ติดต่อเจ้าหน้าที่] → บันทึกการติดต่อ → ⏩ +30 ชม. → "ค้างเกิน 48 ชั่วโมง — Escalate" → Escalate ระดับ 2 → timeline มีครบ
4. **ส่งผลกลับ** — ตัวจำลอง: เสร็จ + ส่งผลกลับ → "ส่งผลกลับแล้ว รอคุณประเมิน" → ประเมินผล → ปิด / ติดตามต่อ (กลับเป็นกำลังดำเนินการ + นัด 14 วัน) / ส่งต่อหน่วยงานอื่นเพิ่ม

ทดสอบเพิ่ม: ร่างรอความยินยอม → บันทึกความยินยอม → ส่งต่อเลย · ออฟไลน์ → error → ลองใหม่สำเร็จ · รีโหลดแล้วข้อมูลอยู่ครบ · 375px ไม่ล้นจอ

## เชื่อมกับหน้าอื่น

- **เส้นทางโอกาส (`PlanCaseView`)** — ปุ่มส่งต่อในเคสใช้ `CreateReferral` ตัวเดียวกัน การส่งต่อของเด็กคนนั้นแสดงพร้อมสถานะจริงใต้การ์ดขั้นถัดไป กดแล้วไป `/referral?ref=ID`
- `/referral?child=ID` เปิดขั้นตอนส่งต่อของเด็กคนนั้นทันที
- การส่งต่อและการนัดติดตามเขียน `CaseLogEntry` ที่มี `refId` ด้วย — งานของครูหน้าแรกนับว่าช่วยแล้ว แต่ timeline ข้ามหน่วยงานไม่แสดงซ้ำ

## ยังไม่ได้ทำ

- ฝั่งหน่วยงานผู้รับจริง (ตอนนี้มีแค่ตัวจำลอง) — บทบาท `agency` ยังเห็นหน้ากำกับดูแลเดิม
- แนบไฟล์เอกสารประกอบ (ช่อง "เอกสารประกอบ" เป็นไม่บังคับและยังไม่มีที่อัปโหลด)
- การแจ้งเตือนจริงเมื่อเกิน SLA (ตอนนี้แสดงในหน้า ไม่มี push)
- ตัวจำลองเลื่อนเวลาได้เฉพาะการส่งต่อที่ครูสร้าง ข้อมูลตั้งต้นคำนวณเวลาจากจำนวนวันที่เปิดมา
