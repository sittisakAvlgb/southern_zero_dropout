# Prompt สำหรับเริ่มงาน (แปะใน Claude Code หรือ AI ตัวอื่น)

ไฟล์นี้มี prompt สำเร็จรูป 3 แบบ — **คัดลอกทั้งบล็อกไปวางเป็นข้อความแรก**

---

## 1. Prompt เริ่มงานครั้งแรก (ใช้ครั้งเดียว)

```text
ฉันเพิ่ง clone โปรเจกต์นี้มาและจะเริ่มทำงานบน branch dev

ก่อนทำอะไร ขอให้อ่าน 4 ไฟล์นี้ตามลำดับ แล้วสรุปให้ฉันฟังสั้น ๆ ว่าเข้าใจอะไรบ้าง:
1. CLAUDE.md
2. docs/ux-redesign-brief.md
3. docs/ux-redesign-gap-analysis.md
4. skill.md

จากนั้นช่วยทำ 3 อย่างนี้ก่อนลงมือเขียนโค้ด:
- รัน npm install แล้ว npm run dev เพื่อให้แน่ใจว่าเปิดโปรเจกต์ได้
- ล็อกอินดูให้ครบทั้ง 4 บทบาท (สพฐ. · สพท. · ผอ.สถานศึกษา · ครู)
  บัญชีเดโมอยู่ใน src/auth/roles.ts รหัสผ่านทุกบัญชีคือ demo
  สนใจบทบาท "ครู" เป็นพิเศษ เพราะเป็น primary user ของโปรเจกต์นี้
- บอกฉันว่าหน้าไหนที่ brief ขอให้แก้ มีของอยู่แล้วบ้าง และขาดอะไรจริง ๆ

ยังไม่ต้องแก้โค้ดในรอบนี้ ฉันอยากเข้าใจระบบก่อน
```

## 2. Prompt สำหรับงานชิ้นแรก — หน้าข้อมูลเด็กรายบุคคล

เริ่มที่งานนี้เพราะ **ใช้ข้อมูลที่มีอยู่แล้วทั้งหมด ไม่ต้องแตะ data layer หรือระบบสิทธิ์** และไม่ต้องรอคำตอบจากเจ้าของโปรเจกต์

```text
งาน: ปรับหน้า src/pages/Student360.tsx ให้ตอบ 3 คำถามตาม Definition of Done
ใน docs/ux-redesign-brief.md ได้ทันทีที่เปิดหน้า — เกิดอะไรขึ้น / อะไรสำคัญที่สุด /
ต้องทำอะไรต่อ

มี 3 จุดที่ต้องแก้:

1) กล่องข้อเท็จจริง 4 ใบ (สถานะติดต่อผู้ปกครอง / บันทึกการเยี่ยมบ้าน / เจ้าของเคส /
   ขั้นตอนของเคส) ตอนนี้ render ด้วย component ชื่อ Fact ที่ท้ายไฟล์ ซึ่งวาดเป็น
   กรอบ rounded-xl + label 10px + ค่า 13px ทำให้หน้าตาเหมือน <input disabled>
   ทั้งที่มันคือข้อเท็จจริง ไม่ใช่ฟอร์ม และทำให้ "ติดต่อผู้ปกครองไม่ได้" ซึ่งเป็น
   สัญญาณอันตราย ดูมีน้ำหนักเท่ากับ "เจ้าของเคส" ซึ่งเป็นข้อมูลธรรมดา
   → เปลี่ยนเป็นแถวสถานะที่ใช้สีและไอคอนสื่อความหมาย ไม่ใช่กล่องเทา 4 ใบเท่ากัน

2) คะแนนความเสี่ยง (เกจเลขใหญ่) ไม่บอกทิศทาง เด็กที่ขึ้นจาก 40 เป็น 85 ใน 8 สัปดาห์
   กับเด็กที่ 85 มาทั้งปี เป็นคนละสถานการณ์ แต่แสดงเหมือนกัน
   → เพิ่ม sparkline กับตัวเลขเดลต้าใต้เกจ ข้อมูลมีอยู่แล้วที่ student.attendance
   (8 สัปดาห์ต่อคน) และมี component src/components/ui/Sparkline.tsx อยู่แล้ว

3) เกจคะแนนกับเหตุผลว่าทำไมถึงได้คะแนนนั้น ถูกแยกด้วยการคลิกแท็บ
   ทั้งที่ "ทำไมถึง 85" คือคำถามแรกที่ครูต้องใช้อธิบายผู้ปกครอง
   องค์ประกอบ 6 ตัวพร้อมน้ำหนักอยู่ใน RISK_WEIGHTS ที่ src/lib/risk.ts
   และค่าแต่ละตัวอยู่บน student (attendanceRisk, academicRisk, behaviorRisk,
   familyRisk, wellbeingRisk, parentRisk)
   → ทำให้เห็นองค์ประกอบพร้อมเกจโดยไม่ต้องเปลี่ยนแท็บ

ข้อควรระวัง:
- ผู้ใช้คือครู และครูบางท่านอายุมาก → ขนาดตัวอักษรต้อง "เพิ่ม" ไม่ใช่ลด
  ตอนนี้ label 10px เล็กเกินไปอยู่แล้ว ห้ามใช้ affordance ที่ต้อง hover
  เพราะมือถือแตะไม่ได้ และห้ามแลก contrast กับความสวย
- framer-motion มีอยู่ในโปรเจกต์แล้ว ใช้ได้เลย ไม่ต้องลง library เพิ่ม
- ตรวจผลที่ความกว้างมือถือ (375px) ด้วย ไม่ใช่แค่ desktop

เสร็จแล้ว npm run build ต้องผ่าน แล้วให้ฉันดูภาพก่อน/หลัง
```

## 3. Prompt ที่ใช้ซ้ำได้ทุกครั้งที่เริ่มงานใหม่

```text
อ่าน CLAUDE.md ก่อน แล้วทำงานนี้บน branch dev เท่านั้น ห้าม push เข้า main

[เขียนงานที่ต้องการตรงนี้]

กติกาที่ห้ามผิด:
- ทุกหน้าที่อ่านข้อมูลต้องผ่าน useScopedData() ห้ามอ่าน dataset ดิบ (เรื่อง PDPA)
- ปุ่มที่ทำงานกับเคสต้องผ่าน canWorkCases() บัญชี สพฐ./ศอ.บต. เป็น read-only
- รูปใน public/ ใช้ assetUrl() จาก src/lib/asset.ts ห้ามเขียน "/logo.png" ตรง ๆ
- ห้ามแก้ base ใน vite.config.ts เป็น subpath (จะทำให้เว็บ Netlify พัง)
- ข้อความในคอมโพเนนต์ที่ใช้ร่วมกันต้องผ่าน useI18n() ไม่ hardcode ไทย/อังกฤษ

ก่อนบอกว่าเสร็จ: npm run build ต้องผ่าน และเปิดดูของจริงในเบราว์เซอร์
ทั้งขนาด desktop และมือถือ (375px) อย่าบอกว่าเสร็จถ้ายังไม่ได้เห็นหน้าจอจริง
```

## ⚠️ 4 เรื่องที่ต้องถามเจ้าของโปรเจกต์ก่อน — อย่าให้ AI เดาเอง

ถ้างานที่ทำแตะเรื่องเหล่านี้ **หยุดแล้วถามก่อน** รายละเอียดอยู่ใน
[ux-redesign-gap-analysis.md](ux-redesign-gap-analysis.md)

1. การเปลี่ยนลำดับชั้นการนำทาง (จังหวัด vs เขตพื้นที่) — กระทบ scope ซึ่งเป็นแกน PDPA
2. การเก็บ activity ของครู — เก็บระดับโรงเรียนหรือรายบุคคล
3. การลดความสำคัญของทะเบียนเด็กนอกระบบ — ลดได้ แต่ถอดไม่ได้ (TOR ๔.๓)
4. การเพิ่มหน้าที่ครูเข้าถึงได้ — เป็นการตัดสินใจเชิงสิทธิ์ ไม่ใช่ UI
